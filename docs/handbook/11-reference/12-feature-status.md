# Feature Status

Status values are **specified and implemented**, **partially implemented**, **specified but not implemented**, **historical/exploratory**, or **explicitly excluded**. A repository revision and evidence are required before claiming implementation.

> **How to read this page:** definitions describe the normative target and do
> not by themselves mean a feature is available in the compiler. For the
> implementation matrix and evidence, see the [Zirk feature status
> catalog](../../init/ZIRK_FEATURE_STATUS.md). In particular, concurrency
> delivery is mixed: structured scopes, channels, `parallel`, scalar
> `Atomic<T>`, native `Thread.run(fn)` on supported 64-bit targets, and scoped
> `Mutex<T>.with` are delivered. The separate `Thread<T>` handle and the other
> language synchronization primitives remain unavailable. The reviewed Phase 5
> completion slice passed the Linux x86_64/aarch64, macOS aarch64, and Windows
> x86_64 CI matrix; this does not establish execution on other targets.

`universal-to-string-and-multiline-strings` delivers universal value rendering
and `'''` literals. `add-canonical-formatter` delivers canonical whole-document
formatting in the CLI, LSP, and browser package; its evidence is the formatter,
CLI, LSP, browser-contract, and corpus verification recorded with that change.

The optional browser-hosted interpreter is tooling, not language-target
delivery. It currently has a bounded verified-IR baseline for selected scalar,
string/output, nullable, direct-call, capability-preflight and resource-limit
paths. See the browser support matrix for the executable subset and exclusions;
native delivery rows do not imply browser execution support.

The type taxonomy, Decimal and Float families, grapheme Char, shared mutable String, binding
permissions, native operators, temporal family, callable types, escaping
closures, projection-copy semantics, object/contract model, complete generics,
algebraic data, collections, and matching rules are authorial definitions even
where compiler delivery is pending.

The same applies to mandatory `Result`, checked explicit exceptions, implicit
typed runtime exceptions, patterned catch, resource responsibility, combined
cleanup failure, the single `requires` capability list, exact-resource runtime
consent, and requester-aware permission validation.

Managed-memory strategy neutrality, weak/dependent references, deep graph
clone, transactional unsafe rollback, irreversible commit, typed structured
tasks, aggregation, fair selection, transfer/share derivation, and safe-code
data-race freedom are also final definitions even where delivery is pending.

The table's language and compiler rows were audited on **20 August 2026**;
standard-library delivery evidence is refreshed on **22 October 2026** in the
[feature status catalog](../../init/ZIRK_FEATURE_STATUS.md). The archived
phase change and its tests are evidence for a completed delivery slice. A
later implementation change must update the relevant status owner when it
changes a row; documentation design alone must not promote delivery status.
LSP, IDE-query, and debugger evidence is refreshed on **23 October 2026**; native
debugger and Devin acceptance limits remain explicitly open.

Explicit Zirk 1.x exclusions include browser/WebAssembly, public runtime directives, standalone `worker`, `async fn`, public event loop, textual inline assembly, general `comptime`, general `defer`, multiple class inheritance, traditional function overloading, `Result` propagation `?`, and public ownership/RC semantics.

The intended surface now includes exponentiation, descending and stepped ranges,
Python-style slicing, classic and iterable `for`, `do ... while`, regex literals,
optional-`fn` lambdas, constructor signatures, mapped traditional enums,
generators, comma-grouped patterns, tuple/object destructuring, `Fn` callable
values, and bound methods. Compiler support may trail this target; consult milestone diagnostics
rather than treating absence in the current parser as a language exclusion.

Remaining artifacts include a complete generated machine grammar and exhaustive
public diagnostic catalog. Stable diagnostic-code policy and many assigned
codes already exist; missing catalog coverage does not make accepted language
semantics open.
