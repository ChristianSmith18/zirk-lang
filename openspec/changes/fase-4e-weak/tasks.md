Design note: implemented as `Base::Weak(u32)` (an id into a new `weak_types: Vec<Type>` interning table), not `Base::Weak(Box<Type>)` as tasks.md's own wording suggested — matching `Base::Pointer(u32)`'s actual shape exactly (the precedent this task explicitly says to parallel) rather than the proposal prose, which predates checking that precedent's real representation.
- [x] 1.2 Resolve `Weak<T>` type references: reject `T` that is not a reference type, reusing `Checker::is_reference_type` (already used by the `inmut::strict` alias matrix) — spec scenario "Disallowed value-type referent". New code `WEAK_DISALLOWED_REFERENT` (E0449).
- [x] 1.3 Type `Weak.from(value: T): Weak<T>` as a compiler-recognized static call (same treatment `Pointer.from` already has — not routed through user generic-class static-method resolution). Unlike `Pointer.from`, no `unsafe` boundary required (spec says so explicitly) and the argument is the value itself, not an addressable place (`value: T` is already a reference).
- [x] 1.4 Type `.upgrade()` as `T?` (nullable `T`, the referent's own type) and `.is_alive` as `Boolean`, on any `Weak<T>`-typed receiver.
- [x] 1.5 Checker unit tests: `Weak<Int32>`/`Weak<SomeRecord>` rejected; `Weak<SomeClass>` accepted; `Weak.from`'s result type; `.upgrade()`'s result type is nullable; `.is_alive`'s result type is `Boolean`. `cargo test -p zirk-sema`: 373 passed, 0 failed.

Design decision taken (not resolved by design.md): whether `Base::Weak` participates in the `is_reference_type` strict-alias matrix (D11). Left excluded (`is_reference_type`'s `_ => false` default), mirroring `Base::Pointer`'s own precedent, which is also excluded from that match — design.md is silent on this and the closest analogous built-in reference-like type already made the same choice.

## 2. IR (zirk-ir)

- [x] 2.1 Define the WeakCell allocation shape (design D1/D2): one field (the target pointer), header carries the reserved sentinel descriptor instead of a real class descriptor. Implemented as `IrType::Weak(u32)` (an id into `weak_types`), with `IrType::is_managed_reference` returning `true` for it — a `Weak<T>` value is itself a managed pointer (to the WeakCell), unlike `Pointer<T>`'s raw pointer, so it must participate in shadow-stack root enumeration and the per-class GC field-offset table (`gc_reference_paths`) the same way `Object`/`Contract` do.
- [x] 2.2 Add IR instructions: `WeakFrom` (allocate a WeakCell, store the target's address), `WeakUpgrade` (read the target field, produce the nullable result), `WeakIsAlive` (read the target field, produce a `Boolean` null-check).
- [x] 2.3 IR-level tests: `Weak.from`/`.upgrade()`/`.is_alive` lower to the expected instruction shapes (`weak_from_upgrade_and_is_alive_lower_to_the_expected_instructions`); confirmed by an explicit test, not assumed, that `WeakUpgrade`'s `Marker?` result slot AND the `Weak<Marker>` handle slot itself are both included in the enclosing function's `gc_roots` (`weak_upgrade_result_and_the_handle_itself_are_both_gc_roots`). `cargo test -p zirk-ir`: all passing (2 new + all pre-existing, including `verify()` on every compiled module).

## 3. Codegen (zirk-codegen-llvm)

- [x] 3.1 Emit the WeakCell's reserved sentinel descriptor as a single fixed LLVM global symbol (`zirk_rt_weak_cell_descriptor`), declared once (`crates/zirk-codegen-llvm/src/runtime.rs`, external linkage, defined in `zirk-runtime`), referenced by every `WeakFrom` allocation site's header initialization. A second global, `zirk_rt_weak_cell_ever_allocated`, is declared the same way for design's own risk mitigation (skip the weak-clearing pass when nothing was ever allocated) — `WeakFrom` stores `1` into it directly (a plain store, no runtime call), since single-threaded correctness needs nothing more.
- [x] 3.2 Emit `WeakFrom`/`WeakUpgrade`/`WeakIsAlive` as direct loads/stores against the WeakCell's single field (no special calling convention needed — an ordinary heap allocation with one field), reusing the same `alloc` runtime call `Alloc` itself uses for the allocation, and a fixed `weak_cell_struct_type` (header + one field) shared by all three instructions for the field's offset.

## 4. Runtime (zirk-runtime) — collector integration

- [x] 4.1 Add the reserved sentinel descriptor symbol itself (`crates/zirk-runtime/src/collector.rs`) — a single fixed static (`zirk_rt_weak_cell_descriptor`, `#[unsafe(no_mangle)]`) the mark/weak-clearing passes compare object headers against, its address exposed to codegen via a matching external global declared in `crates/zirk-codegen-llvm/src/runtime.rs`. A second static, `zirk_rt_weak_cell_ever_allocated`, backs task 4.3's own skip check.
- [x] 4.2 Mark: when tracing an object whose descriptor is the WeakCell sentinel, mark the cell itself (it is an ordinary allocation reachable like any other) but do NOT recurse into its target field as a strong edge (design D2).
- [x] 4.3 Weak-clearing pass (design D3, `clear_dead_weak_cells`): between mark and sweep, walk the intrusive allocation list once; for every marked WeakCell, if its target's mark bit is unset, null the WeakCell's target field. Skip this pass entirely when no `Weak<T>` has ever been allocated (`zirk_rt_weak_cell_ever_allocated`, design's own Risk mitigation) — confirmed skipped by an explicit instrumentation-hook test (`clear_dead_weak_cells_runs_only_once_a_weak_cell_has_been_allocated`, a `#[cfg(test)]`-only run counter), not assumed.
- [x] 4.4 Runtime unit tests (mirroring `collector.rs`'s existing `#[cfg(test)]` style, same synthetic-object approach `fase-4e-colector-mark-sweep`'s own tests use): `a_weak_cells_target_that_survives_collection_keeps_being_observed`; `a_weak_cells_target_that_is_collected_has_its_field_nulled_not_dangling`; `an_unreachable_weak_cell_is_collected_like_any_other_object`; `a_weak_cells_target_field_is_never_traced_as_a_strong_root` (synthetic graph where the *only* path to an object is through a WeakCell — collected anyway). `cargo test -p zirk-runtime`: 32 passed, 0 failed (6 new).

## 5. Cross-cutting correctness tests (do not skip — same standard as the collector itself)

- [x] 5.1 End-to-end `.zrk` fixture: `Weak.from(obj)` while `obj` is still reachable — `.upgrade()` returns it, `.is_alive` is `true`. `weak_upgrade_and_is_alive_see_a_still_reachable_referent` (`crates/zirk-cli/tests/end_to_end.rs`) — real subprocess run, output `true\n42\n` confirmed.
- [x] 5.2 End-to-end `.zrk` fixture: the only strong reference to an object is dropped (goes out of scope), a collection is forced (`ZIRK_GC_THRESHOLD`, the mechanism `fase-4e-colector-mark-sweep`'s own e2e tests already use), then `.upgrade()` returns `null` and `.is_alive` is `false`. `weak_upgrade_and_is_alive_see_a_collected_referent_as_gone` — real subprocess run, output `0\nfalse\ngone\n` confirmed against a forced `ZIRK_GC_THRESHOLD=1` collection; this genuinely exercises the weak-clearing pass end to end through real codegen (a wrong/missing D3 pass would either crash on a dangling read or print the stale id `7`, not `gone`). Design correction found while writing this: `stdout.println(<Int32>)` does **not** allocate through the collector at all (`Int`→`String` conversion is `zirk-runtime/src/string.rs`'s own allocation path, outside `zirk_rt_alloc`'s reach, per `collector.rs`'s own `needs_allocation`/`is_managed_reference` doc comments) — the fixture had to construct a second throwaway object (`Marker(0)`) to actually cross the tiny forced threshold; documented here since the same trap would silently produce a false-negative-passing test for anyone extending this suite.
- [x] 5.3 End-to-end `.zrk` fixture: a `Weak<T>` handle does NOT keep its referent alive — construct an object, take a `Weak<T>` of it, drop every strong reference, force a collection, confirm the object is gone even though the `Weak<T>` handle itself is still reachable. `a_reachable_weak_handle_does_not_keep_its_referent_alive` — output `0\nfalse\n` confirmed: `w` stays reachable through `main`'s own local the entire time, yet `.is_alive` still goes `false`, proving a `Weak<T>` handle is never treated as a strong root (design D2's whole reason for the sentinel descriptor).
- [x] 5.4 Ran `LLVM_SYS_201_PREFIX=/opt/homebrew/opt/llvm@20 cargo test --workspace` repeatedly (3x clean, all green — see note below); `cargo clippy --workspace --all-targets` clean (fixed `ptr_eq`/`unnecessary_cast`/`double_must_use` findings); `cargo fmt --check` clean after `cargo fmt`.

**Concurrency bug found and fixed while running 5.4, not part of the original design:** the first run of `cargo test --workspace` flaked exactly once, in `zirk-runtime`'s own unit test `a_weak_cells_target_field_is_never_traced_as_a_strong_root` (not one of the section-5 e2e tests — the runtime's own `#[cfg(test)]` suite from task 4.4). Root cause: `zirk_rt_weak_cell_ever_allocated` is intentionally a real process-global `static mut`, not `thread_local!` like every other piece of collector test state — correctly so, since it must reflect one running *program's* history, not one test worker thread's (design's own risk-mitigation counter). But `cargo test`'s default multi-threaded harness runs `#[test]`s concurrently across several OS threads, and every collector test's `reset_state()` unconditionally reset that global to `0` — so one thread's `reset_state()` could race a *different* thread's still-in-flight `collect()` that needed the flag `true`, silently skipping the weak-clearing pass for that other thread's test. Fixed by adding a `static TEST_GUARD: Mutex<()>` in `collector.rs`'s own test module, serializing every collector test (`reset_state()` now returns the held `MutexGuard`, bound for the whole test body) — confirmed fixed by 3 clean full-workspace runs after the fix, none flaking. This is a test-isolation artifact of running single-threaded-program-shaped global state under a multi-threaded test harness, not a bug in the collector's actual single-process runtime behavior (nothing in a compiled Zirk program touches this flag from more than one thread until Phase 5 introduces `thread` at all).
