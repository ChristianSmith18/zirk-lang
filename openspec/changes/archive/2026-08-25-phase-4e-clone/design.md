## Context

`fase-4e-colector-mark-sweep` (merged) gave every managed object a real header (descriptor + `next` + `size`) and a shadow stack that correctly roots every managed reference, including SSA temporaries spilled to synthetic slots. `fase-4e-weak` (merged) proved a compiler-synthesized allocation shape (WeakCell) with its own header sentinel composes cleanly with mark/sweep. `Clone` needs a third kind of runtime operation on top of the same substrate: a full graph traversal that allocates new objects while preserving the shared/cyclic structure of the old graph, using a temporary memoization map that must itself survive collection for the duration of one `clone()` call.

## Goals / Non-Goals

**Goals:**
- `clone()` creates new identity for every cloned reference object reachable from the root being cloned.
- Internal sharing is preserved: two fields that alias in the source graph alias in the new graph (pointing at one shared new clone), never two independent copies.
- Cycles are reproduced without infinite recursion or stack overflow on a cyclic graph.
- The source graph is never mutated and no alias to a cloned *mutable* source node is retained by the result.
- A graph reaching a `Resource`, `Pointer<T>`, lock, `Task`, or other non-`Clone` member is rejected at compile time, not at runtime.
- The clone operation itself is collector-safe: the in-progress result graph and the memoization map are both reachable from shadow-stack roots for the entire duration of one `clone()` call, so a GC triggered mid-clone (by one of clone's own allocations crossing the threshold) cannot collect a partially-built clone or its bookkeeping.

**Non-Goals:** (see proposal's "Explicitly out of scope".)

## Decisions

### D1: Derivation eligibility is a compile-time transitive-closure check over declared field types, not a runtime capability probe

For a `class`/`record`/`value class` `C`, the checker derives `Clone` for `C` iff every field's declared type is itself `Clone` — recursively, following the same transitive-closure shape `is_reference_type`'s alias matrix and the strict-alias checker already use for a different property. A field whose type is `Pointer<T>`, a `Resource`-derived type, `Task<T>`, or any synchronization type (`Mutex<T>`, `RwLock<T>`, etc.) makes `C` non-`Clone`, full stop — no partial/best-effort derivation. A field whose type is a user class without `Clone` (declared or derivable) does the same, propagating transitively.

Alternative considered: allow a class to opt into `Clone` even with a non-`Clone` field by requiring a manual `clone()` body that doesn't touch that field. Rejected for the *derived* case — derivation is specifically the "every field is `Clone`" shortcut; a class wanting anything more specific already has the manual-implementation escape hatch (out of scope for this change's compiler machinery beyond normal method compilation), so derivation itself stays a simple, fully-automatic rule with no partial cases to reason about.

### D2: Runtime representation is one graph-clone entry point plus a per-call memoization table, not a per-class generated "deep copy" function baked at compile time

`zirk_rt_clone_begin(): *mut CloneCtx` allocates a memoization table (address → address) scoped to one top-level `clone()` invocation; `zirk_rt_clone_lookup(ctx, source_addr) -> Option<dest_addr>` and `zirk_rt_clone_record(ctx, source_addr, dest_addr)` back it. The IR lowering for `x.clone()` on a class `C` with derived `Clone`: call `clone_begin` (only at the *outermost* `.clone()` call — a field of reference type recurses into a shared per-call context, not a fresh one per field, which is exactly what makes sharing/cycles work); for the root object, `clone_lookup` first (handles the degenerate case where the root itself is reached again through a cycle, though the common case is a fresh table with nothing recorded yet); allocate the new object; `clone_record(ctx, source_addr, new_addr)` *before* recursing into any field (this ordering is what makes cycle-safety possible — a field that points back at an ancestor already has a recorded mapping by the time the recursive call reaches it, so it looks up the in-progress clone instead of recursing infinitely); for each reference-typed field, recursively clone the field's value: `clone_lookup` the field's source address first — if already recorded (shared reference already cloned, or a cycle back to an ancestor), reuse that mapping; if not, clone it fresh and record it. Value-typed fields are copied directly (no identity, no lookup needed). At the outermost call's return, `clone_end(ctx)` releases the memoization table.

Alternative considered: generate a distinct compile-time `clone_C(source): C*` function per class `C`, mutually recursive with its own fields' clone functions, with the memoization table threaded as an explicit parameter through every generated function. Rejected — functionally equivalent to the chosen design but adds a whole class of new compile-time-generated-function machinery (name mangling, mutual-recursion-across-classes handling, one function per class multiplied across the whole compiled program) for no behavioral difference from a single generic runtime entry point parameterized by the per-class field-layout table the collector's own tracer (`gc_reference_paths`) already walks. Reusing that existing per-class field-offset table (built for mark's tracing) as clone's own field-walk driver keeps this change from inventing a second copy of "how to enumerate a class's reference-typed fields."

### D3: The memoization table and every clone allocation created so far are shadow-stack roots for the whole call, via the same synthetic-slot spilling mechanism the collector already applies unconditionally

`fase-4e-colector-mark-sweep`'s D4 already spills *every* managed-reference-typed instruction result to a synthetic root slot the instant it's produced — this is unconditional, not something clone's lowering needs to opt into specially. The memoization table itself (`CloneCtx`) is not a managed Zirk object (it's a `zirk-runtime`-internal allocation, outside the collector's object header/mark/sweep machinery entirely, same category as the frame stack itself) — but every *value* it stores an address for is already independently rooted by the synthetic-slot mechanism at the point each recursive `clone()` step's result was produced. No new rooting mechanism is needed; this decision exists to document *why* not, since it's the first place this change could plausibly need to invent one.

### D4: Compile-time rejection walks the same transitive field-type closure as D1, reported at the point `Clone` is required (derivation site or `T from Clone` generic-bound check), not lazily at `.clone()` call sites

If `C` cannot derive `Clone` (D1) and the program calls `.clone()` on a `C` value or requires `C: Clone` through a generic bound (`zirk-type-system`'s "Generic projection needs Clone" scenario), the checker reports the failure at that use site, naming the specific field (or transitive path) that broke the chain — matching the existing "STRICT_ALIAS_VIOLATION"-style diagnostic precedent of naming the concrete offending member rather than a generic "type is not Clone" message. New diagnostic code in the `E04xx` range (checker), next available after `E0449` (`WEAK_DISALLOWED_REFERENT`).

## Risks / Trade-offs

- **[Risk] A deeply nested or highly-shared graph produces one memoization-table entry per distinct object, which is unbounded by the graph's own size** — no different in principle from the graph itself, but worth naming: `clone()` is not O(1) or bounded independent of input. → Accepted: this is the correct, spec-required behavior (preserving sharing needs remembering every object seen), not a design flaw; no mitigation needed beyond what the spec already implies.
- **[Risk] Recursive traversal (D2) risks native call-stack depth on a very deep non-cyclic graph** (a long linked list, say), distinct from the cycle case D2 already handles via memoization. → Accepted as a known limit, consistent with how this compiler already handles deep native recursion elsewhere (no general stack-safety guarantee exists yet); flagged here rather than silently discovered later. A future change could convert the traversal to an explicit worklist if this proves material.
- **[Trade-off] D1's "every field must be `Clone`, no partial derivation" is stricter than some languages' clone semantics** (which might skip a field or default it). → Accepted: matches this change's own compile-time-rejection requirement exactly as `MEMORY_AND_UNSAFE_SEMANTICS.md` states it — silently skipping a field would violate "creates new identity for every cloned reference object."
