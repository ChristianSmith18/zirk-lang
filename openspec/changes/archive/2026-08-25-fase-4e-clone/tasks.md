## 2. Checker (zirk-sema)

- [x] 2.1 Add the `Clone` trait as a compiler-recognized built-in contract (parallel treatment to how `Weak<T>`'s element-type restriction reused `is_reference_type` — check the actual current representation of built-in contracts/traits before assuming a shape). Implemented as a real `ContractType` pushed by `Checker::register_native_clone_contract` (mirroring `register_native_iteration_contracts`'s "inject the tables directly" pattern), but deliberately with an **empty** method table — see that function's own doc comment: `.clone()` is never dispatched through a vtable at all, so the contract entry exists only so `implements Clone`/`T from Clone` resolve to a real name.
- [x] 2.2 Derivation eligibility (design D1): for a `class` (see deviation below), walk its field types transitively; derive `Clone` iff every field type is itself `Clone`. No partial/best-effort derivation. **Deviation**: restricted to `ClassKind::Class` only — `record`/`value class` are excluded (`Checker::class_is_clone`'s own doc comment: they have no identity of their own, and this change's IR/codegen only builds the reference-graph traversal, not a `Value`-typed entry point). **Deviation**: `Task<T>`/lock types are not yet real compiler types (`pending_type`'s own `PHASE_5` list) so cannot appear as a field at all — no rejection code needed for them today. **Deviation**: enum-typed fields (`Base::Enum`/`Base::EnumInstance`) are conservatively excluded too, not derived — found while writing end-to-end tests: `BuildEnum`'s codegen only initializes the *active* variant's fields, leaving every other variant's own field slots undefined, which the collector's/Clone's shared field-offset walk reads unconditionally regardless of which variant is active (a real, if latent, hazard predating this change) — documented in `Checker::is_clone_type`'s own doc comment; fixing it for every enum shape is out of this change's scope.
- [x] 2.3 Compile-time rejection (design D4): implemented at both the `.clone()` call site (`Checker::check_derived_clone_call`) and the `T from Clone` generic-bound check (`Checker::satisfies_constraint`'s own new branch), naming the specific field/transitive path (`Checker::find_non_clone_path`). New code: confirmed next-free is `E0450` (after `E0449` `WEAK_DISALLOWED_REFERENT`) — added as `codes::NOT_CLONE`.
- [x] 2.4 Type `.clone(): T` on any `Clone`-eligible receiver type `T` — `Checker::check_method_call_on`'s own new gate (bare, no-arg `.clone()`, no user-declared `clone` method) plus `Checker::check_param_call`'s own `T from Clone` special case.
- [x] 2.5 Checker unit tests added to `crates/zirk-sema/tests/typing.rs` (9 new, all passing): scalar-only class derives; `Clone` class-typed field derives; `Pointer<T>` field rejected naming that field; a class `implements Resource<E>` rejected; a non-Clone nested class field rejected naming the transitive path; `T from Clone` accepted/rejected; `implements Clone` written explicitly accepted; a manual `clone()` implementation dispatched as an ordinary method (bypassing derivation even with an otherwise-disqualifying field). `cargo test -p zirk-sema`: 382 passed, 0 failed (373 pre-existing + 9 new).

## 3. IR (zirk-ir)

- [x] 3.1 Define graph-clone IR instructions. **Deviation from design D2's literal instruction shape** (`CloneBegin`/`CloneLookup`/`CloneRecord`/`CloneAlloc`/`CloneEnd`): implemented as a single `InstKind::Clone(Operand)` instead — see its own doc comment in `crates/zirk-ir/src/ir.rs` for the full reasoning, matching the rigor of `fase-4e-weak`'s own `Base::Weak(u32)` vs `Box<Type>` deviation note. Short version: a `class` receiver may at runtime be a more-derived subclass than its static type, so the field walk needs the object's own runtime descriptor (exactly what the collector's `mark_object` already does) rather than a compile-time-baked, declared-type field offset list; the whole recursive traversal was moved into one generic runtime entry point (`zirk_rt_clone`) driven by the exact same descriptor-embedded field-offset table (`gc_field_offsets`) `mark_object` already reads, which is what `design D2`'s own "Alternative considered" already argued for at the dispatch level — this applies that same reasoning one layer further, to the whole walk, and is what makes the operation correct for a polymorphic receiver, not merely simpler.
- [x] 3.2 Lower `x.clone()`: `Checker::method_of`-style re-derivation in IR (`is_derived_clone_call`, mirroring `is_weak_method_call`'s own pattern of re-deriving from the receiver's IR type rather than consulting a sema-provided resolution table) — a manually-implemented `clone()` method is dispatched as an ordinary call; the derived case lowers to one `InstKind::Clone`.
- [x] 3.3 Confirmed (not assumed) the synthetic-slot spilling from `fase-4e-colector-mark-sweep`'s D4 covers `InstKind::Clone`'s result: it is `IrType::Object(_)`, already `is_managed_reference`, so the existing unconditional spill applies with no change — verified by the explicit test in 3.4.
- [x] 3.4 IR-level tests added to `crates/zirk-ir/tests/lowering.rs` (3 new, all passing): `.clone()` lowers to `InstKind::Clone`; its result is included in the enclosing function's `gc_roots` (explicit test, same rigor as `fase-4e-weak`'s task 2.3); a manually-implemented `clone()` method lowers as an ordinary call, not `InstKind::Clone`. (No `CloneLookup`/`CloneRecord`-sequence test, per the 3.1 deviation — that machinery now lives entirely in the runtime, covered instead by `crates/zirk-runtime/src/clone.rs`'s own unit tests in section 5.) `cargo test -p zirk-ir`: 18 passed (verification/lowering suites, including `verify()` on every compiled module).

## 4. Codegen (zirk-codegen-llvm)

- [x] 4.1 Emit `InstKind::Clone` as one call into `zirk_rt_clone` (`crates/zirk-codegen-llvm/src/emit.rs`'s new match arm; symbol/declaration added to `crates/zirk-codegen-llvm/src/runtime.rs`'s `Runtime`/`symbols` — same declaration pattern `alloc` already uses). Per the 3.1 deviation, there is no separate field-recursion loop to drive at the codegen level for a `class` receiver — the field walk lives in the runtime, reusing `gc_field_offsets` directly (task 4.1's own "reuse... rather than duplicating a second field-offset walker" instruction, applied at the runtime layer instead of codegen).
- **Correctness fix found while building this section's own end-to-end tests, not originally scoped**: `InstKind::NullValue`'s codegen (`emit.rs`) left an absent nullable's payload slot `undef` rather than zeroed, on the documented assumption that "nothing reads it without checking the flag first." That assumption is false: the collector's own `mark_object` (pre-existing, `fase-4e-colector-mark-sweep`) and this change's own `zirk_rt_clone` both read a nullable-*reference* field's payload directly off the object's byte layout with no flag check, trusting it to be null when absent — an `undef` payload can lower to any bit pattern, which crashed `Clone`'s own traversal the moment it dereferenced one as a pointer. Fixed by zeroing the payload (`ty.const_zero()` instead of `ty.get_undef()`) — strictly safer, no behavior change for any code that already only reads a nullable's payload after checking its flag. This was a latent bug in the collector itself, not `Clone`-specific; documented in `NullValue`'s own doc comment.

## 5. Runtime (zirk-runtime)

- [x] 5.1 **Deviation from the literal `zirk_rt_clone_begin`/`_lookup`/`_record`/`_end` FFI shape** (consequence of the 3.1 deviation): implemented as one exported entry point, `zirk_rt_clone(source) -> dest` (`crates/zirk-runtime/src/clone.rs`), with the memoization table (`HashMap<usize, *mut c_void>`) as a purely internal local, scoped to one call via an internal recursive helper (`clone_recursive`) — never exposed as separate begin/lookup/record/end FFI calls, since nothing outside this one Rust function ever needs to drive the traversal step by step. Collector-safety (design D3, `zirk-object-memory`'s own added requirement) is handled by a new thread-local extra-root list (`CLONE_ROOTS`) that `collector::mark` walks in addition to the ordinary shadow stack — every destination object is pushed the instant it is allocated and given a valid descriptor, before any of its own fields (which may trigger further allocations/collections) are populated.
- [x] 5.2 Runtime unit tests, `crates/zirk-runtime/src/clone.rs`'s own `#[cfg(test)]` module (4 new, all passing): a leaf clone gets new, independent identity; a shared child clones to one new shared clone (`b.left is b.right` true, `b.left is a.left` false — the spec's own named invariant, exercised directly at the runtime level too, not only end to end); a self-referential cycle terminates and stays within the new graph; a collection forced mid-clone (`ZIRK_GC_THRESHOLD`-equivalent, direct threshold manipulation) does not corrupt the still-in-progress clone. `cargo test -p zirk-runtime`: 36 passed, 0 failed (32 pre-existing + 4 new).
