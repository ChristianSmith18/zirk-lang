## 2. IR/lowering verification (design predicted no change needed for the direct self-reference case — this was WRONG, found and safety-netted, not fixed for real)

**Rescoped, not blocked.** Verifying task 2.1 (not assuming it) surfaced a real, reproducible stack overflow: `IrType::is_managed_reference` (`crates/zirk-ir/src/ir.rs:359-383`) recurses through `module.enums[id].fields` with no cycle guard, and every enum lowers as an **inline-flattened struct** (`emit.rs`'s `enum_struct`) with no indirection for any field, ever — so `Cons(tail: IntList)` asks for an infinitely-sized LLVM type, not a fixable-in-one-function bug. Fixing this for real needs automatic heap indirection ("boxing") for a self-referential field: a new `IrType` case, a runtime allocation kind, GC root/tracing rules, and codegen for it — none of which exists today. That is a substantially larger, cross-cutting IR/codegen/GC design than this change's own declaration-order scope, and is **not** built here. Instead (task 1.4), the checker now rejects the specific unindirected shape with a clean `NOT_LOWERED` diagnostic before it ever reaches this crash — the same discipline every other checked-but-not-yet-compilable construct in this codebase already follows.
