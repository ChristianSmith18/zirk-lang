The complete Zirk reference

One searchable map of the syntax, semantics, type system, runtime, project model and compiler decisions recorded throughout 01_plantilla_zirk.md.

Resolution rule. The template is the exhaustive inventory. When an older answer conflicts with ZIRK_LANGUAGE_SPEC.md, ZIRK_RUNTIME_SPEC.md, ZIRK_STDLIB_SPEC.md or ZIRK_COMPILER_SPEC.md, the newer normative document wins.

1. Identity and philosophy

Zirk is a general-purpose, statically typed language for native applications, backend services, CLI, desktop, systems and libraries. Source uses .zrk, the executable is zirk, dependency locks use zirk.lock, and packages use .zpkg. It is high-level by default and exposes explicit low-level operations only where control is required. Simplicity, native performance, safety, readable concurrency, fast incremental compilation and low memory overhead guide the design.

2. Lexical syntax, bindings and scope

TopicRule
BlocksBraces; indentation is formatter-owned.
SemicolonsOptional when unambiguous; canonical formatter adds them.
Comments//, /* … */, and documentation blocks.
CaseIdentifiers are case-sensitive.
Namingsnake_case values/files, UpperCamelCase types, UPPER_SNAKE_CASE constants/globals.
AliasesOriginal -> Alias in import and destructuring.

mut permits reassignment. inmut fixes the reference while respecting the type's own mutability. inmut::strict prevents transitive modification. Types may be inferred locally; public contracts should remain explicit. Every type has a default value, while flow analysis rejects unavailable reads.

Scopes are block, function, file/module and application. Top-level declarations stay private until share. Globals exist only in an application's init.zrk and each file enables them through use NAME. Confusing shadowing is diagnosed. Parameters are immutable bindings unless explicitly mutable.

3. Types, literals and value semantics

Every value belongs to a semantic class rooted at Object, although value types can live inline without heap allocation. Signed integers span Int8–Int128; unsigned types mirror them; decimals span Decimal16–Decimal128. Int/Integer and Dec/Decimal are fixed aliases rather than platform-dependent sizes.

Boolean is strictly true/false. String is mutable, Unicode-aware and semantically indexed by graphemes; explicit bytes(), chars() and graphemes() views expose lower levels. Char represents one Unicode semantic character. Special types include Void, Never, Null and Object.

Width-specific literals use constructors such as Int8(10). Scientific notation uses e; valid underscore grouping is preserved. Normal overflow, division by zero, bounds errors and invalid casts fail in a controlled way. Wrapping, saturating and checked behavior is explicit. T? is T | Null; safe access is ?. and fallback is ??.

4. Operators, control flow and functions

== is structural equality and is tests identity. Comparison, arithmetic, exponentiation, compound assignment, prefix/postfix increment and Boolean-only && || ! are built in. The ternary evaluates one branch. 0..10 excludes its end; 0..=10 includes it. Operator implementations follow reserved language contracts and cannot change precedence.

Control flow includes if/else, for, for … in, while, loop, break and continue. The final spec permits if as a compatible-branch expression. match is a statement in statement context and an exhaustive value in expression context; it matches values, types, unions, algebraic enums and destructuring.

Functions support optional/default/named/variadic parameters. Zirk uses unions, generics or distinct names instead of traditional overload sets. Lambdas are ordinary function values. Closures capture immutable values safely; mutable captures require lifetime and concurrency proof. fn gen creates generators implementing iterator contracts.

5. Objects, contracts and algebraic data

Classes use construct, instantiate without new, and access the receiver through this. Members are public by default with private/protected. A class may extend one class and implement multiple interfaces and traits. Classes and methods can be abstract; classes are inheritable by default.

Interfaces describe contracts; traits can include reusable implementation. Records are immutable structural data. Value classes are compact identity-free domain values. Enums may be traditional or algebraic with associated values. type creates aliases and A | B creates unions. Generics use <T>, constraints use from, and implementations may specialize concrete types.

Value types copy according to their value contract; objects retain identity. Deep cloning is never implicit: clone() exists through an explicit trait and can be derived only when every field supports cloning. Equality and identity stay separate.

6. Collections, slicing and iteration

The standard model includes dynamic Array<T>, fixed arrays whose size participates in the type, List<T>, Map<K,V>, Set<T>, lazy Range<T>, iterators and views. Access is checked; safe lookup returns a nullable/algebraic value. Strings and sequences support [start:end:step] slicing and negative indices where meaningful.

Iterable<T>/Iterator<T> power for … in. map, filter and reduce never mutate their source. The pipe operator |> passes the previous result forward.

7. Errors, assertions and resources

Result<T,E> represents expected failure and is handled explicitly with exhaustive match; there is no implicit postfix propagation operator. Typed exceptions handle unusual recoverable failures through try, catch<E>, default and finally. fatalError terminates irreparable state after safe diagnostics and cleanup.

Resource<E> plus match with closes on success, error, exception, return and cancellation, and prevents resource escape. Plain match allows manual transfer. Version 1.x deliberately has no general defer, using, public destructor mechanism or destructor-based RAII. assert remains active in release; tests prefer richer expect diagnostics.

8. Memory, pointers, intrinsics and SIMD

Stack/heap placement is selected by layout and escape analysis. Automatic management hides ownership syntax and guarantees safe code against use-after-free, uncontrolled null dereference, out-of-bounds memory and undefined behavior. GC/reference-counting details are runtime architecture, not source semantics.

Safe references are non-null and lifetime checked. Pointer<T>, dereference, raw memory, reinterpretation and unchecked FFI require unsafe {}. Unsafe never disables types, scopes, mutability or permissions.

There is no textual inline assembly in 1.x. Portable intrinsics cover bit operations, explicit overflow modes, atomics, fences and memory primitives. Vector<T,N> provides portable explicit SIMD alongside automatic vectorization; LLVM selects AVX, NEON, multiple instructions or a scalar fallback while preserving safety rules.

9. Concurrency, parallelism and scheduling

Workers are composition, not a separate primitive. Cancellation is cooperative, typed and hierarchical. Timeouts use Duration literals (500ms, 5s, 5m, 5h). I/O waits are cancelable. Shared mutable captures and globals used by parallel/thread require proof, synchronization or atomics.

10. Modules, manifests, packages and permissions

Files form modules. share exposes code, import incorporates it, and use only enables globals. Relative imports are quoted and omit .zrk; standard/package paths are symbolic.

init.zrk is a declarative DSL for project, build_targets, globals, permissions, compile_permissions, requires and dependencies. It cannot contain entry logic, global imports or arbitrary compiler/runtime code. Applications grant final authority; libraries only declare requirements. Installation never grants permissions.

zirk.lock records exact versions, origins, hashes, transitive dependencies, IR compatibility and target-native variants without credentials. A .zpkg contains a manifest, inspectable public API, portable typed IR, license and documentation. Source may be included. zirk prepare audits missing and unused permissions; builds remain non-interactive and strict.

11. Targets, FFI and platform boundaries

Initial native output covers supported Windows PE, Linux ELF and macOS Mach-O combinations across x86, x86_64, armv7 and aarch64. Target resolution is CLI override, manifest targets, then host. Cross-compilation also depends on SDKs, linkers and compatible native dependencies.

The stable interoperability boundary is the C ABI. C++ and Rust expose extern "C" wrappers. Explicit FFI exports receive stable symbols; internal name mangling is private. Native/dynamic libraries need declared high-risk permissions and target-compatible artifacts.

WebAssembly, browser, DOM, browser events, fetch and platform-specific source directives are outside Zirk 1.x. They can be added later without redefining the native core.

12. Decorators, reflection and syntax tooling

fn dec defines compile-time decorators with typed target blocks. They inspect authorized metadata, issue source diagnostics and produce transformations that are reparsed, resolved and checked. They cannot mutate the compiler's private semantic AST or access filesystem/network/processes without compile_permissions.

Basic type identity is always available; structural reflection is retained only when requested and cannot bypass visibility or mutability. There is no general comptime {}. External tooling uses a public, immutable, versioned Syntax API retaining tokens, spans, comments, invalid nodes and incomplete code.

13. Compiler, CLI, testing and binary stability

The pipeline is incremental lexer → syntax tree → module/name resolution → types/flow → validated decorators → portable typed IR → LLVM IR → native object/linker. LLVM is the sole initial backend. Formatter, linter, check and LSP do not invoke LLVM.

SystemContract
DiagnosticsSeverity, stable code, source span, cause and actionable help.
FormatterCanonical, deterministic, idempotent, comment-preserving.
LinterTyped analysis; safe fixes only; checks results, tasks, resources, races and permissions.
LSPIncremental completion, hover, navigation, rename, semantic tokens and actions.
DebuggerDWARF/PDB mappings for values, stacks, threads, tasks, channels and expansions.
DebugFast builds, complete symbols, checks and source correspondence.
ReleaseInlining, DCE, escape analysis, devirtualization, monomorphization, vectorization and LTO without weaker semantics.
IncrementalContent fingerprints invalidate only affected implementation, API, decorators, permissions or targets.
CompatibilityPublic API plus versioned portable IR; no universal native ABI promise.

Tests use @test only in .spec.zrk, E2E uses @e2e in test/*.e2e.zrk, and benchmarks use @bench. Test permissions are separate; runners detect abandoned tasks, live threads, leaked resources, timeouts and exceptions.

14. Explicit non-features in 1.x

  • No undefined, numeric truthiness, silent overflow or silent undefined behavior.
  • No new, traditional overload sets, implicit shell, user-controlled event loop or dependency-granted authority.
  • No implicit result propagation, general defer, public destructors, inline assembly or multiple maintained backends.
  • No browser/DOM/Wasm target, UI framework, ORM or complete web framework in the core.
  • No stable internal name mangling or native ABI guarantee across all compiler versions.
