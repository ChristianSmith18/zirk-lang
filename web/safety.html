Failure without ambiguity

Errors, resources and safety

Expected failure is data, exceptional failure is catchable, and irreparable failure ends the process with a diagnostic.

Result<T,E>

Operational failures use Result and explicit exhaustive matching. Zirk deliberately has no postfix ?; propagation remains visible at the point of control flow.

result.zrk
match User.load(id) {
    Ok(user) { stdout.println(user.name); }
    Error(NotFound) { stderr.println("Missing user"); }
    Error(error) { report(error); }
}

Exceptions and fatal errors

exception boundary
try { execute(); }
catch<HttpError> error { stderr.println(error); }
default error { log(error); }
finally { metrics.flush(); }

Exceptions represent unusual but recoverable failures. fatalError(message) is irreparable and terminates after the safest possible diagnostic and cleanup. Bounds errors, division by zero, null misuse and invalid state never silently become undefined behavior.

Resources and match with

resource-safe file access
inmut first = match with File.open("data.txt") {
    Ok(file) { file.read_line() }
    Error(error) { "" }
};

A Resource<E> acquired by match with closes on success, error, exception, return or cancellation. It closes before the branch value is delivered and cannot escape directly or indirectly.

Memory guarantees

Safe Zirk promises no use-after-free, uncontrolled null dereference, data races in protected concurrency contexts, or undefined behavior. Index checks remain unless the compiler proves them redundant. Automatic memory management does not expose ownership syntax; explicit pointers and memory reinterpretation stay inside unsafe.

Scope of unsafe. The block grants concrete low-level operations. It never disables types, lexical scopes, mutability rules or declared capabilities.

Capabilities and permissions

Applications declare runtime access to files, network, processes, environment and other sensitive capabilities in init.zrk. Compile-time decorators have a separate compile_permissions boundary. The runtime canonicalizes paths where necessary to prevent .. and symlink escapes.

Native interoperability

The stable native boundary is the C ABI. C++, Rust and other ecosystems expose extern "C" wrappers. Native dependencies must match target and ABI; the compiler rejects incompatible packages early. Reinterpretation and guarantee-removing casts require unsafe.
